## C. Failure, security, state and resource analysis

- Input: missing/null/nonstring/wrong-case correlation, invalid timestamp/generation, JSON Schema integer decimal/exponent spelling, negative/zero/out-of-range values and huge exponents are checked before use. Bounded lexical parsing prevents big-power allocation. UTF-8 Text and predecode1MiB bound apply independently of Binary size. Unknown optional fields are ignored; malformed trace is discarded. Path parse enforces nonempty Read/Save and schema character ceiling; Service enforces owning canonical POSIX UTF8 path bytes/segments/control/percent/symlink rules without normalization.
- Attach/request: credential is captured from the same authenticated Control dial. URL denies userinfo/query/fragment; WSS uses normal certificate verification; test CA trusted explicitly, no InsecureSkipVerify. Attach reply refers to that ATTACH message; request and result refer to their own message, fileRequestId/Lab/gen/op. Data never selects another VM. Provider validates current designated Workspace and physical server even with cached SSH, with host-key callback retained.
- Wire: exactly one request/result; binary is not JSON parsed or text rewritten. Empty binary remains a message. Save reads exactly one declared Binary before dispatch; configured oversize finite body is drained without allocation and returns TOO_LARGE, malformed length/order1008; hard global frame bound1009 can leave mutation outcome unknown. Tree checks full serialized envelope1MiB and returns no partial success. Failed Read emits no binary. SafeError is fixed9-code mapping and unknown raw errors become INTERNAL_ERROR/UNAVAILABLE, never their original text.
- State: synchronous admission plus process-lifetime hash tombstones prevent active/completed/canceled ID redial across Control reconnect. Close-before-Open prevents resurrection; wrong Lab/gen cannot close an active request. Bounded16384 rememberedIDs fail closed on new requests, no eviction. Active capacity16 rejects new work without affecting active requests. These operator limits are documented, not new wire fields. No File socket retry/reconnect loop exists.
- Ownership: reader epoch is captured before its goroutine starts and accompanies dispatch/disconnect. A delayed old frame cannot bind to new credential/sender or tombstone/close new-owner requests. Child owner ctx prevents an OPEN paused during retirement from admitting work; ctx checked under admission lock. Process cleanup follows each particular request. Notifications use captured sender and finite separate deadline to avoid canceling the shared Control writer on a File cancel; owner-invalid work cannot notify a new connection.
- Resources: each request owns one Data socket/cancel/reader/done and each SFTP operation owns a channel, bridge pair, bounded slot and refcounted path lock. Cancellation kills that channel's helper before CLOSE, keeps ownership through exec ACK with existing Manager setup budget, joins owned workers before releasing service slot. The Control/SFTP/PTY owners remain separate; shutdown File requests precedes existing managers. Fake Close ACKs do not replace actual OpenSSH EOF evidence. Setup ACK/Signal/TCP blackhole can still retain internal bounded work until shared transport retirement; caller timeout does not imply every remote worker immediately exited. Do not kill shared PTY to conceal that limitation.
- Partial mutation/restart: Service uses same opened file handle, revision comparison before write/truncate, owns a copied body and retains path lock until worker drain. External writers/filesystem atomicity and forced-midwrite I/O are outside these guarantees. Lost Save result is never automatically replayed; new Read reconciles state. Remembered IDs are ephemeral across process restart; SaaS must follow no-replay unknown Save contract, not resend an old mutation ID. Durable File request recovery was not added or required by150.
- External cleanup: each real VM run tracks7 Provision resource IDs and cleanup queries exact absence after reverse deletes. Auxiliary integration-created management SG/keypair deletes use baseline helpers; a separate read-only prefix list validates their final absence. That prefix check may conflict with a concurrent integration run; it never deletes other resources. No arbitrary unowned VM/filesystem/global SSH teardown is performed.
- Limits: real SaaS database/credential rotation/Browser/HTTP UI, paid KT Cloud, reset/cleanup full OP02/C2, network packet blackholes, actual ENOSPC/EIO/EDQUOT and mid-Save packet loss are unexecuted. Existing loopback errors are not these real incidents. Their scope and inherited SFTP risk are explicit; no confirmed unresolved defect is reclassified as a limit.
