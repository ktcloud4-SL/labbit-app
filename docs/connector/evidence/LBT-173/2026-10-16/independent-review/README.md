## Reproduction

Requirements: repository's configured Go toolchain and already-downloaded `golang.org/x/crypto v0.57.0`. From repository root in PowerShell:

```powershell
pwsh -NoProfile -File docs/connector/evidence/LBT-173/2026-10-16/independent-review/reproduce.ps1 -Mode control
pwsh -NoProfile -File docs/connector/evidence/LBT-173/2026-10-16/independent-review/reproduce.ps1 -Mode fault
```

Both commands passed on the final source. They use `combined-probe_test.go.txt` through a Go overlay. The fault mode copies x/crypto to a fresh external temporary directory, then changes only server-side inbound `direct-tcpip` handling to ignore SSH CLOSE. All PTY traffic remains functional. A temporary `-modfile` replace selects that copy. Neither repository source nor GOMODCACHE is patched. Go disallows module-cache file replacement through an overlay, so the initial tooling attempt was replaced by this explicit temporary module copy.

This deliberately non-cooperating SSH peer is a fault fixture, not a claim about normal OpenSSH behavior. It tests local cancellation and resource ownership even when one channel receives no CLOSE acknowledgement. The fixture's keys are generated ephemeral test keys; credentials or private keys are not copied into these artifacts.

The optional mutation command is expected to fail only the EOF-budget probe, proving the regression assertion detects loss of the final SSH CLOSE ownership condition:

```powershell
pwsh -NoProfile -File docs/connector/evidence/LBT-173/2026-10-16/independent-review/reproduce.ps1 -Mode fault -MutateEOFBudget
```

Each command prints its external output directory. `.go.txt` suffixes keep embedded probe sources out of ordinary `go test ./...` package discovery. The temporary peer module is intentionally not committed. The script does not remove caller-provided directories.
