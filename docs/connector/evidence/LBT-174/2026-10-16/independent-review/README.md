# Independent review evidence

`initial-base`, `firstpass`, `secondpass` are historical observations, including findings which were open at that point. `final/README.md` is the final review. All original reports/logs remain unchanged. The reviewer did not mutate production source or cloud resources.

To reconstruct a review copy outside the active checkout:

1. Export base `4691c0ae8a43955549ae2b9e8bc4f5a464c30001` for historical stages, or `0051d8d6803fd447f7b690dd895a0a928c3c7302` for `final`: `git archive --format=tar --output=review-base.tar <base>`, then extract into a new directory. Avoid Windows PowerShell text pipelines for binary tar data.
2. In that new exported directory, run `git init -q` before applying patches. This creates an isolated Git root: without it an enclosing repository can make `git apply` silently skip the exported files even with exit code 0.
3. For first/second/final snapshots apply that folder's `reviewed-source.patch` in the exported copy (`git apply --check`, then `git apply`). Patches include the uncommitted implementation/test files from the pinned reviewer snapshot, excluding separate probes. The production final source is also available as the parent `source-diff.patch`.
4. Before adding probes, compare every Go/module source with the stage's `snapshot-manifest.json`, normalizing CRLF to LF before SHA-256. Missing files and hash differences must both be zero; for `final`, the parent `source-manifest.json` gives the exact 495-file mapping and aggregate `956c7d6f3b87f6d49d1b842571124da4591db40f5bc15de5c6efce9d65fe98b9`. An exit code of 0 from Git alone is insufficient. The final reconstruction checks preserve both the unisolated failure and isolated success.
5. Copy each `probes/*.go.txt` into the exported copy as `.go` at its `probe-paths.json` path. For `initial-base`, `zz_independent_test.go.txt` belongs to `internal/connector/preview`, and `zz_independent_preview_owner_test.go.txt` to `internal/connector/wss`.
6. Run the stage's README commands. Probes use local Fake/loopback peers; they do not call OpenStack. Historical defect probes are expected to FAIL at their original revision, while fixed final probes PASS.

The historical `retirement-overlay.json` contains the reviewer's absolute external paths and is retained as diagnostic metadata. Rewrite its `Replace` key to the exported copy's absolute `internal/connector/wss/handler.go` and value to a local `.go` copy of `handler-retirement-scheduling-overlay.go.txt`, then pass `-overlay <rewritten.json>` to `go test`. That complete overlay is the pinned handler source plus a 20ms scheduling delay just after the authority lock release inside `onControlDisconnected`. It adds scheduling pressure only; it must not be applied to the production checkout. Each stage has its own source-specific overlay. This makes the old interleaving deterministic and confirms the final retirement snapshot survives the same scheduling fault.
