## 1. External exact SSM loopback transport

A protected optional Database DialAddress can be a reasonable minimal transport boundary if default behavior remains unchanged and it accepts only a literal approved loopback IP+valid/pinned local port, not arbitrary host, URL, wildcard, Unix socket, remote IP or DSN option. Keep parsed DSN's exact actual RDS Host/Port/Name/User, no fallback/runtime options, TLS verify-full/actual RDS ServerName/root CA/minimum TLS and fixed RDS Describe metadata checks unchanged. Override only the dial destination; do not rewrite DSN Host to localhost or relax TLS because the wire travels through SSM. Always honor caller context/connect deadline. Account for pgx DNS/LookupFunc behavior when overriding DialFunc, and independently test that no unexpected direct dial or alternative fallback can occur.

Local accepting port is not remote DB identity. External coordinator must bind exact current admin3 STS, existing management EC2 ID/ownership, approved official SSM remote-host forwarding Document and actual exact RDS host+5432 parameters, fresh session/process/port and complete cleanup. Preserve actual DSN hostname verification on server handshake; do not use shared Secret modification, global hosts entries, DB SG/IAM changes or arbitrary tunnels to make an existing guard pass. Local port hijack/unrelated listener must fail TLS/identity/route checks. Readonly VerifySQL is not proof of Single Writer or remote physical Fencing. Transport session termination may proceed after UNKNOWN, but journals/authorizations/control state must be retained and not automatically replayed.

Minimum regressions: absent-field legacy config; invalid/nonliteral/nonloopback/zero/invalid port rejection; DSN actual Host/Port/Name/User mismatch; TLS disabled/insecure/wrong servername/multihost/runtime-option rejection even with loopback; controlled fake dial sees only approved loopback; canceled dial/cert errors; no production target fallback. External SSM cleanup retains exact session history/active absence/child process/closed port checks reviewed earlier.

## 2. Immutable signed bytes storage

Use unique scoped approval/observation prefix/key for current request, protected source bytes, expected bucket owner and explicit Osaka region; conditionally create only (`If-None-Match:*`) with SSE and versioning. No overwrite/retry after ambiguous response. Require returned non-null VersionId, then exact-version independent readback of bytes length/SHA and encryption metadata before forming Reference. Preserve Put/readback request/response metadata and timestamps; keys and DSN never uploaded. Receipt success is stored signed bytes only, not actual command authorization or DR GO. Existing Synthetic read access is not proof of new prefix write permission; validate current policy/bucket/Principal scope separately before writes. Never reserialize signed JSON after hashing/signing or substitute latest version. Unknown PUT must HOLD while inspecting exact scoped object/version rather than create new key/approval to retry. Keep EnableExecution=false and no journal/action calls in storage verification tool.

## 3. Two-second strategy and tradeoffs

Do not change owning callback2-second timeout, proof TTL or final Begin/Apply time validation merely to make tests pass. Prefer maintaining fresh wire semantics if feasible: long-lived fixed official-region S3 SDK client can use one immutable GetObject with VersionId/expected owner and verify delete marker, returned version, bounded ContentLength/body size and SHA. Existing Head ETag adds no identity guarantee over immutable version+exact bytes hash. Omitting Head is an explicit owning Runtime/test change, not silent weakening. Ensure profile/credential Principal provenance, fixed endpoint/TLS (no arbitrary env/config endpoints), bounded response/error output and context/retry limits. New dependency/transport code requires full audit and actual callbacks measured; a fast individual request is not end-to-end proof.

Alternative with fewer dependencies: invocation-local immutable-byte preload, after exact authentication and before bounded verification callbacks. Cache only exact Reference tuple bytes (bucket/key/version/size/SHA), cap document count and256KiB each, verify bytes before insertion, return defensive copies, no mutable/global/cross-invocation cache and no cache-miss network fallback. Every callback still revalidates signature/purpose/key/principal/request/phase/observed/request validity using current clock, and Begin/Apply retain proof time checks. Never cache parsed PASS, identity, proof or approval decision. Overall invocation deadline and time elapsed during download remain enforced, and expiration means a new legitimately approved request rather than extended old TTL.

**Important compatibility constraint, reported to parent before code:** unconditional CLI preloading before Execute would make historical APPLIED/INTENT/inspect dependent on missing/expired original artifacts, unlike current authenticated historical lookup semantics. Inspect must issue no artifact access. Authenticated execution should first preserve exact existing historical lookup outcome (including UNKNOWN/conflict); only a new invocation should preload, followed by existing Resumer/Restrictor lookup recheck and Begin CAS. The duplicate lookup is needed for concurrent creation. Do not derive historical status from cached files. Race to new APPLIED after preload remains protected by normal inner lookup/CAS.

Preloading changes freshness of bucket access observation: a delete/ACL revoke after download is not observed during callback, even though signature/TTL/request checks stay fresh. Explicitly decide/document this snapshot semantic; do not claim callback performed a fresh S3 authorization check. If that semantic change is not intended, prefer SDK fresh Get. Restriction init/Pause and Resume need equivalent treatment, while inspect/history must keep zero artifact calls.

Required regressions: exact bytes/reference cache hit+defensive copy; wrong/version/hash/size/owner/missing/canceled preload never creates INTENT; key/purpose/request/target/phase failures retained; fake clock expiration after preload and between authorizer/rechecker/beforeBegin/beforeApply; unsigned/unverified preload cannot produce proof. APPLIED/INTENT/inspect (including absent artifacts) preserves historical behavior with artifactRead0. Duplicate concurrent invocation still uses store CAS and never reapplies UNKNOWN. Cache failure does not auto retry network/mutation. Real callback timers and total invocation duration measured separately; remote signing approval/fencing cannot be faked by transport success.
